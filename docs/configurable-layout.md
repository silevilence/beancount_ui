# 业务类型、记录模板与文件布局

在侧栏「账本 → 布局与模板」打开「文件布局与业务模板」：左侧是业务列表与新增入口，右侧是选中业务的编辑面板，底部固定显示预览日期与「检查并预览布局 / 启用此布局」。可保留五种内置业务，也可添加 `lunch` 等自定义业务。未配置时沿用 MyBill 默认路径及原有表单；录入端只提交业务类型和记录内容，不传物理文件路径。

1. 在「概览与入口」中修改账本入口，并按表格核对各业务的目标文件与包含链；表格会标出与生效配置不同的业务。
2. 选择某个业务，编辑名称、记账语义（仅自定义业务可选，启用后不可更改）、目标文件、路径日期来源和索引链。索引每行一个路径，按顺序从入口逐级 include 到目标文件；留空表示入口直接包含目标。面板中的「包含链预览」按预览日期解析日期占位符，并标出已有与新建文件。
3. 需要记录模板时打开「使用记录模板」：原文是唯一来源，工具栏把常用占位符插入光标处，字段可逐项调整名称、类型与填写方式（用户填写 / 固定值 / 自动当天），「填写示意」按当前日期展示渲染结果，字段行的「重命名」会同步改写原文中的占位符。
4. 选择预览交易日期，点击「检查并预览布局」。预览按业务列出目标及包含链，仅展示所选日期所需的 include 差异；选择实际写入日期的业务使用服务器当天。内部仍检查下一年 1 月的 include 规则，但不把跨年校验的示例文件混入展示差异。
5. 检查后点击「启用此布局」。修改表单会清除旧预览；其他窗口更改配置或外部文件变化后，需要重新预览。关闭前仍存在未启用的修改时会要求确认。

启用只更新独立状态目录的 `layout.json`，不会写入预览示例或移动历史数据。实际保存新记录时才创建必要文件与索引，继续使用原来的完整账本校验、互斥写入、幂等请求与中断恢复机制。历史编辑和删除保持原文件位置。

## 路径与规则

所有路径相对于账本根目录，使用 `/` 分隔，文件扩展名为 `.bean` 或 `.beancount`。允许中文、字母、数字、下划线、连字符和点；不接受绝对路径、上级目录、反斜杠、空路径段、隐藏路径、Windows 保留文件名、空格或任意格式表达式。`gnucash/` 历史导入目录保持只读。

每种业务的目标和索引都可以使用固定路径（例如 `a.bean`），或 `{year}`、`{month}`、`{day}` 占位符（四位年、两位月、两位日，每种在一个路径中至多出现一次），例如 `{year}/{month}.bean`、`salary/{year}.bean`。各业务分别选择日期来源：

- **交易日期**：最终 Beancount 指令里的日期，即消费或记录发生的日期。
- **实际写入日期**：服务器的上海时区当天，独立于交易日期；例如 10 月 1 日补记 9 月 30 日，可写到 10 月文件，记录仍保留 9 月 30 日。

同一业务的目标和整条索引链使用相同日期来源。预览后跨日时，依赖实际写入日期或自动当天字段的请求不能直接保存，需取消并重新预览；已完成请求的重试仍返回原结果。

索引链每行是一个完整的账本相对路径，从固定入口往下填写。例如目标 `records/{year}/{month}/{day}.bean`，索引链为：

```text
index.bean
years/{year}.bean
months/{year}/{month}.bean
```

写入时依次维护 `main.beancount → index.bean → years/2026.bean → months/2026/10.bean → records/2026/10/01.bean`，各 include 使用相对于父文件的路径。动态父文件继续由上一层包含，最终到固定入口；支持最多 64 层索引。留空则入口直接 include 目标。配置不接受通配符，已有 include 通配符及间接包含关系仍可复用，避免重复 include。

规则检查覆盖不同业务、数据文件与索引、文件与目录、大小写别名及 include 循环。日期模板按所有可能数字展开的范围保守检查交集，而非只检查预览日期；潜在重叠也会被拒绝。历史启用过的路径保留业务归属，不能重新用作其他业务或索引，避免旧收益被重新归类。

例如，可保留入口 `main.beancount`，使用以下布局：

| 业务 | 目标文件 | 索引链（按顺序） |
| --- | --- | --- |
| 日常、订单、转账 | `journal/{year}-{month}.bean` | `index.bean` → `indexes/{year}.bean` |
| 余额宝收益 | `business/yuebao.beancount` | `index.bean` → `indexes/business.bean` |
| 工资奖金 | `business/salary.beancount` | 同上 |
| 话费 | `business/phone.beancount` | 同上 |
| 余额断言 | `business/balance.beancount` | 同上 |

每个索引字段填写实际路径，每行一个；表中的“同上”不是输入值。工资文件仍保留或创建 `salary` 标签范围；余额宝查重、日期列表和模板推荐同时识别默认与历次启用的专项文件。

## 记录模板与填写项

关闭记录模板时，日常与话费使用内置消费表单，余额宝与工资使用收入表单（到账金额、收入账户、资产到账账户），余额断言使用原文输入。自定义业务按其记账语义选择同样的默认入口；设置概览及编辑面板会显示实际录入方式。日常和收入表单均可切换原文高级编辑，已启用模板则按模板字段填写。

模板是一条完整 Beancount 交易原文，余额业务是一条 `balance`。固定内容可以直接写在原文里；可配置部分以 `{{name}}` 表示，同一字段可多次引用。金额取负值使用 `{{-name}}`，不支持代码、函数或任意表达式。

例如只填写日期和金额，其余内容固定：

```beancount
{{date}} * "午餐"
  Expenses:Food {{amount}} CNY
  Assets:Cash {{-amount}} CNY
```

将 `date` 定义为「日期 / 用户填写」，`amount` 定义为「金额 / 用户填写」。想把交易日期固定为写入当天，则把 `date` 改为「自动使用保存当天」；录入页面只剩金额。界面提供「填入完整消费表单示例」，可开放商户、摘要、分类账户、付款账户、币种等，再逐项调整。

字段支持三种方式：用户填写（可设默认值）、固定值（不提供输入框）、自动当天（仅日期）。类型为日期、十进制金额、文本、账户、币种、标记或标签。文本自动加引号并转义，不能在占位符外再加引号；占位符必须是独立 token，不能嵌在字符串、注释或账户名称的一部分里。标签/标记须给有效默认值，如 `*`、`#lunch` 或 `^link`。变量也可放在分录、成本、价格或元数据的相应位置；配置时验证语法，实际预览时校验完整账本、账户、日期和交易平衡。

启用后，「随手记一笔」与补记工作台的「日常消费」业务选择均使用相同动态表单；表单顶部列出需要填写的字段，以及由模板生成的固定值、保存当天与币种。固定字段和当天日期由后端生成，不能通过原文、旧表单或 API 覆盖。该业务的原有专用入口（如订单、转账、逐日收益）不能绕过模板；需要这些专用流程时保留内置业务的默认表单，另建自定义业务承载受限模板。自定义业务可选择记账语义，工资保留标签、收益保持按交易日期查重、余额只接受断言；已启用业务不能换语义，请另建标识。

草稿保存配置版本；配置变化后旧请求被拒绝，取回模板草稿后需点击「按新配置重新填写」。新模板只约束新建记录，历史更正仍在原文件保留完整原文。

## 更换入口、切回默认与恢复

新入口必须已经存在、校验通过并保留当前入口下的历史数据和账户等指令。可提前创建一个包含原入口的包装文件，例如 `config/book.bean` 中写入 `include "../main.beancount"`。相对 include 由后端按每个父文件的位置生成，接入和 Git 同步也使用当前入口。

尚未推送的旧提交可能早于新入口文件的创建；同步会使用该提交中存在的历史入口校验。当前入口存在但账本无效时不会回退，非法提交和范围外文件仍会阻止推送。

选择「填入默认 MyBill 布局」后仍需预览和启用。共享根 `index.bean`（如上例）可以让默认入口继续看到新布局写入的记录。如果新入口独有的 include 链未被默认入口覆盖，切回时会提示历史记录缺失；请先在默认入口的包含链中纳入这些数据，再重新预览。应用不为切换布局自动隐藏、移动或删除记录；纯 include 包装文件可以退出包含链。

切换会使尚未保存的交易预览失效，需返回表单或草稿重新预览，生成新的请求标识。已经保存的原请求重试仍返回已完成结果，不重复记账。配置损坏时停止使用它并提示恢复，不静默退回默认规则。

账本与整个状态目录仍须一起备份；`layout.json` 含当前规则及历史业务归属，重启和容器升级会保留。它不会进入账本 Git 提交。其他应用实例必须共享同一个状态目录；独立设备需要部署相同布局状态或自行配置，并保留历史归属。

API：`GET /api/layout` 返回当前及默认布局、`version` 和 `write_day`；`POST /api/layout/preview` 接收 `layout` 和 `day`，返回路由、差异及绑定当前配置、日期与账本内容的 `token`；`POST /api/layout/activate` 提交相同参数及该 token。无效或过期配置不改变当前规则。模板录入提交 `business`、`values`（仅用户输入字段）和 `layout_version`，而非 `raw`、`entry` 或 `order`；单笔和批量均采用此协议。
