## Define：问题与完成标准

日常使用者需要在当前页面明确知道「正在看哪个范围」「操作哪笔订单」「下一步会改变什么」，并能从结果或错误继续操作，而不必反复滚动、猜测入口或到服务器找备份运行记录。

优先修复日期查找、操作上下文、账务与实物语义、结果可追踪性，再统一公共控件细节。保持项目现有深色配色、组件、信息密度和账务规则。

## Develop：采用的方案

- 统计使用明确历史周期快捷入口，复用原日期计算。没有改变用户已选统计粒度。
- 收货按购买日期默认包含今天在内的近 30 天；「上月」「全部日期」「重置筛选」可见。更早待收货有明确提示和直接入口，库存跳转及批次编辑不受默认日期限制。
- 桌面列表、详情各自滚动，选单重置详情滚动而保留列表位置。窄屏保留单列，选单滚到详情、提供返回列表；重复选择同一单也定位。
- 保留两种业务路径：确认实物收货按现行规则处理账单；单独付款用于提前付款、部分付款、退款等，不记录收货或改变库存。未关联 Grocy 的收货表单明确不会更新库存。
- 日志保留最近 200 条手动预览、手动 / 自动备份和自动检查结果，展示时间、来源、结果、耗时及错误摘要。连续无变更检查不重复占满历史。日志在服务端状态目录持久化，不进入账本 Git；不返回原始 Git stderr 或账本正文，摘要脱敏。升级前记录不补造。
