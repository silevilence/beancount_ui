# 阶段四验收记录

日期：2026-09-30；发布目标 `V0.1.0`。

## 回归范围

使用仓库内脱敏 MyBill 结构作为 CI 唯一账本来源。新增 `test_phase_four.py` 将连续补记、同日多笔、
跨月补记、四类专项文件、外币与多分录、淘宝部分结算和两类退款组合到同一使用流程。
每个模拟使用日重建服务对象并重试原请求，核对金额、加载错误、远端提交和无关文件字节。
既有测试继续覆盖并发写入、真实进程中断、外部改动、断网、push 失败、恢复和同步冲突。

`test_release_notes.py` 验证新版本插到顶部后仍精确提取指定版本、忽略版本大小写、保留 Markdown，
并拒绝非法 Tag、章节缺失、重复与空正文；代码围栏中的标题不作为版本边界。

## 发布流程

普通分支及 PR 只运行双平台检查；手动 Release 运行只预演容器。Tag 发布复用完全相同的检查与
容器验证，全部通过后才推送候选镜像和创建 Release。发布正文不混入镜像元数据，完整镜像地址、
摘要和源码提交作为 `image.txt` 附件。版本标签拒绝覆盖，正式运行以 Actions 结果为准。

`container_smoke.py` 在 Linux runner 验证非 root、镜像空数据目录、认证读写拒绝、生产页面、
预览保存、临时远端同步、健康检查、删除重建容器、待确认请求恢复与幂等、同浏览器草稿恢复，
并保留截图与结果。账本与服务状态通过挂载持久化，草稿仍属于浏览器 localStorage。

## 边界

连续使用采用连续业务日期的可重复演练，不代表已经经过五个自然日的生产观察。
真实账本副本仅本地演练，禁止进入源码、镜像或 CI；只输出结构数量和验证结论。
首版没有旧版镜像可以实际降级；本轮验证同一版本容器重建，后续回滚按部署文档和各版本兼容性说明执行。
