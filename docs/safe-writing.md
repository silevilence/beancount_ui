# 保存协议与恢复

1. `POST /api/preview` 接收 UUID `request_id`、当前 `revision` 和输入；业务类型确定新记录的固定文件路由。
2. 后端在隔离副本中更新文件及索引，校验完整候选账本，保存预览并返回每个文件的 diff。
3. `POST /api/commit` 只接受已预览请求。锁内重读文件哈希；任何外部变化都拒绝过期预览。
4. 先用 SQLite FULL 同步持久化 `applying` 恢复记录，再逐文件临时写入、fsync、原子替换；全部完成才标为 `done`。
5. 相同请求 ID 和内容的预览/保存重试返回原结果。同 ID 不同内容拒绝。重启后仍保留结果。

所有应用读写共用按账本绝对路径命名的进程锁；读取前先恢复中断事务，不向界面暴露半个 include 链。
中断事务默认向前完成：逐一核对现场只能是原版或候选版，并核对整本候选版本，再补齐未写入文件。
若恢复时检测到人工修改则停止，保留双方数据和恢复日志，提示人工核对；不会覆盖另一方。

账本与 `BEANCOUNT_STATE_DIR` 必须一起备份；同一账本的所有进程必须使用同一个状态目录。切换目录前先正常停止服务并保留完整状态。
状态库含预览原文和请求结果，应视为私有数据，不提交到 Git。预览不会修改账本。
连接错误或超时后应重试原请求；不要重新创建 UUID。原请求已完成时不会再次入账。

外部编辑器不遵守本应用锁：预览后编辑会被版本校验拒绝；替换前也核对目标内容。
需要同时手工编辑时，应完成编辑并重新加载后再保存。普通文件系统没有跨文件原子事务，崩溃瞬间磁盘可能有部分新文件；服务恢复完成前禁止继续操作账本。
本实现保证本地文件系统上的进程中断恢复；网络共享盘、磁盘故障和断电后的硬件缓存行为不属于此阶段验收范围。

金额在 API 中使用十进制字符串。基础表单只写精确配平的双分录；原文必须是单条受支持指令，并经完整 Beancount 校验。
工资在已有 salary 标签范围内插入；新月与跨年逐级补齐 include，历史内容不重排。

Git 快进也使用独立持久日志 `fast-forward.json`，记录原/目标提交及变化文件前后字节。所有应用读取与写入进入 `Writer.guard()` 后先恢复快进，再恢复保存事务；逐文件替换前再次核对现场，完成后以预期原提交作 CAS 更新分支并恢复索引。文件、分支或暂存区出现外部修改时停止并保留日志和双方内容。恢复日志包含账本原文，与其他状态一起保护，不提交 Git。

快进拒绝忽略文件碰撞、Git 管理路径、路径别名、符号链接、子模块和不支持的文件/目录转换。不要在同步时同时进行手动 Git 操作。需要人工接管中断更新时，先停止服务并备份账本及整个状态目录，依据日志核对双方字节、原/目标提交和索引，再决定恢复；不要直接删除日志或执行硬重置。
