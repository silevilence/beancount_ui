# GitHub 接入与备份

9 月账单已于 2026-09-30 同步至 GitHub。此前 6—8 月分析仍保留为历史基线；首次接入应使用最新 `master-1`，不再等待另一份本地 9 月副本。

设置 `BEANCOUNT_LEDGER_DIR` 为应用代码之外的独立仓库根目录，`BEANCOUNT_STATE_DIR` 为独立持久目录。已有仓库使用 `origin`；空目录克隆需要在服务端设置 `BEANCOUNT_GIT_REMOTE`，默认分支 `master-1`。应用不会覆盖非空目录重新克隆，也不会切换已有分支。

侧栏「GitHub 备份」卡片常驻显示当前状态、远端、待提交、未推送、最后成功与下次检查，顶栏备份徽标和快捷键 `s` 可直接打开「备份中心」；接入、手动同步与定时设置都在该对话框中完成，接入与推送一律先预览再确认。

接入前先预览既有文件变更与未被 include 的文件。需要纳入遗漏文件时勾选后再次预览（选择改变会提示重新预览），核对入口 include 差异并确认接入。接入校验完整账本并检查远端访问；原有账本不会改变，除非明确选择补充 include。自动备份保持关闭。

凭据由运行服务的账户通过 Git credential helper、SSH agent 或挂载的 SSH/Git 配置提供。不要将令牌放入远端 URL、`.env.example`、浏览器或提交中。认证和网络失败保留本地文件，界面提供分类诊断而不返回可能含凭据的 Git 原始错误。

验收仅使用临时仓库和脱敏示例，不向真实 MyBill 仓库推送测试数据。

## GitHub 代理与错误日志

打开「备份中心 → 网络代理」，接入前即可设置，点击「保存代理设置」后重新尝试克隆或同步：

- **跟随服务端配置**（默认）：优先使用 `BEANCOUNT_GIT_PROXY`；未设置时沿用 Git 配置和 `http_proxy` / `https_proxy` / `all_proxy` 等环境变量。
- **自定义代理**：例如 `http://192.168.1.10:7890` 或 `socks5h://192.168.1.10:1080`，支持 HTTP、HTTPS、SOCKS5、SOCKS5H，地址必须含端口且不含凭据、路径、查询参数。SOCKS5H 由代理解析远端域名。
- **直连**：本应用的 Git HTTP(S) 请求不使用 HTTP 代理；覆盖服务端默认代理。

页面设置保存在独立状态目录 `sync.json`，重启后保留，后续克隆、接入检查、fetch 和 push 共用；修改设置不改变自动备份开关。配置只作用于应用启动的 Git 子进程，不写入全局 Git 配置或账本仓库。自定义/直连（以及显式 `BEANCOUNT_GIT_PROXY`）会覆盖匹配远端的代理配置并清空子进程 `NO_PROXY`，避免既有绕过规则使页面选择失效。实现依据 [Git 的 HTTP 代理配置说明](https://git-scm.com/docs/git-config#Documentation/git-config.txt-httpproxy)。

这些设置用于 HTTP(S) 仓库（如 `https://github.com/OWNER/LEDGER.git`）；`git@github.com:...` 等 SSH 地址仍由服务端 SSH 配置处理。需要代理认证时使用服务端已有的 Git/代理配置和凭据助手，并选择「跟随服务端配置」、不设 `BEANCOUNT_GIT_PROXY`，不要将用户名或密码输入页面。

NAS / Docker 中 `127.0.0.1` 指向容器自身。使用 NAS 或局域网代理服务器实际可访问的 IP 和端口，并确认代理允许该容器连接。两个 Compose 文件均透传 `BEANCOUNT_GIT_PROXY`；修改环境变量需重建容器，页面保存立即用于下一次连接。代理功能需要包含此变更的新镜像，已运行的旧镜像不会自动获得功能。

Git 失败会在**服务端控制台**输出 `Git failure` 日志，包含操作名、目标分支、代理模式、退出码/异常类型、耗时和脱敏后的 stderr；45 秒超时同样记录已收到的 stderr。本地启动查看后端终端，NAS 查看容器日志，Compose 可执行 `docker compose logs --tail=100 ledger`（NAS 独立文件用 `docker compose -f compose.nas.yaml logs --tail=100 ledger`）。反馈时提供失败操作及对应日志，可区分 DNS、连接拒绝、认证和分支错误。

日志隐藏 URL 中的认证信息/参数、认证头、常见令牌及密码字段，限制错误详情长度，不记录 Git 标准输出、账本输入或完整命令。浏览器仍只接收操作失败和本地记录保留提示；详细诊断位于服务端日志。修正网络或认证后重试备份，已保存记录无需重新录入。

## 手动同步与恢复

「立即同步」（侧栏卡片或备份中心）先展示允许纳入的账本/include 文件、排除范围、差异统计与提交说明；确认后重新加载完整账本并检查预览版本。保存和同步共用跨进程锁。提交来自已校验快照，不借用用户暂存区；范围外已暂存内容保留。待推送的手动提交也逐个检查范围与账本有效性，含日志等范围外文件时停止并要求人工核对。

Git 提交身份使用账本仓库已有的 `user.name` / `user.email`，缺失时提交失败并保留文件。无变更不创建空提交；推送失败保留已建提交，重新「立即同步」会推送原提交。最后成功时间仅在远端推送成功或核实远端同版本后更新。

远端恢复规则：先 fetch，干净工作区且本地是远端祖先时才快进；快进前校验远端账本，更新后重新加载。远端非法时保留当前有效版本。有任何未处理工作区变更或两侧分叉时停止自动合并。出现未完成 merge/rebase/cherry-pick 或冲突时，自动备份暂停；有效本地账本仍允许保存，带冲突标记的非法账本保持写入门禁。

恢复时先备份两侧文件，在终端人工核对与合并，保留需要的双方记录，完成 Git 操作后在页面重新「立即同步」。应用不强推、不硬重置、不自动选择冲突一侧；暂停期间顶栏与备份卡片显示「备份已暂停 · 需人工处理」并给出处理入口，手动同步成功后解除暂停。断网只影响备份，已保存交易仍可查询和继续记账。

定时备份默认每 300 秒检查、最后观察到变更后等待 60 秒，可在「备份中心 · 定时备份」用开关启停、按预设或自定义间隔调整（可立即用「立即同步」手动执行），并显示下次检查倒计时与调度原因。检查间隔为 5—86400 秒、等待为 0—3600 秒。以账本目录身份建立跨进程执行锁，同一时刻只有一个 worker 执行，检查时间和重试状态保存在独立状态目录。

无有效账本变更且无待推送提交时只检查本地，不进行 fetch/commit/push。连续保存延后备份；正在写入时跳过。账本错误不上传，冲突暂停至人工处理后手动同步成功。网络/服务失败指数退避，最多 1 小时；重启后从实际 Git 历史和持久状态恢复未推送提交。保留状态目录可以保留配置和最后成功时间。

## 访问地址与私网部署

默认 `local` 模式仍用 `uv run uvicorn beancount_ui.app:create_app --factory --host 127.0.0.1 --port 8000`，开发页面为 `http://127.0.0.1:5173`。服务端同时检查连接来源、Host 和 Origin；把监听地址误改为 `0.0.0.0` 不会自动开放账本。

私有网络使用单用户口令，先执行 `npm --prefix frontend run build`，服务端会在同一 8000 端口提供生产页面和 API。配置示例（仅在受控私网或加密 VPN 中使用）：

```powershell
$env:BEANCOUNT_ACCESS_MODE = 'private'
$env:BEANCOUNT_ALLOWED_ORIGINS = 'http://ledger.internal:8000'
$env:BEANCOUNT_ACCESS_TOKEN_FILE = 'C:/private/beancount-access-token'
uv run uvicorn beancount_ui.app:create_app --factory --host 0.0.0.0 --port 8000
```

不想维护访问地址时，可将 `BEANCOUNT_ALLOWED_ORIGINS` 显式设为 `*`；这会取消 Host/Origin
白名单，仍然要求口令认证。留空不等于全部允许。NAS Compose 示例已采用带引号的 `"*"`；
该配置需要包含此修复的镜像；V0.1.0 不支持，V0.1.1 起可用。

口令文件只包含至少 32 字符的随机口令，限制为运行服务的账户可读；也可通过服务端 `BEANCOUNT_ACCESS_TOKEN` 注入。可用 `uv run python -c "import secrets; print(secrets.token_urlsafe(32))"` 在私人终端生成并保存，禁止提交口令文件。页面输入的是应用访问口令，不是 GitHub 令牌。口令仅保存在当前页内存，刷新需重新登录，退出即移除，认证后页面右上角保留「个人访问已认证 / 退出」提示；所有账本读取、写入和备份控制接口都要求认证。健康检查与不含账务数据的登录配置可匿名访问。

默认前端目录为 `frontend/dist`，可通过 `BEANCOUNT_FRONTEND_DIR` 指定部署的纯前端资源目录，不能指向账本或状态目录。服务器时区不影响记账日期，业务日期和界面时间统一按 `Asia/Shanghai` 展示。

应用以个人私网方式运行；外网由 NAS 的 HTTPS 入口终止 TLS，再转发到容器，入口防护、限流与现场验收见[部署说明](deployment.md#局域网与-nas-外网转发)。HTTP 口令不能通过不可信网络传输。生产访问使用构建后的页面，不公开 Vite 开发服务。草稿只保存在当前浏览器，正式账本和服务端状态应持久化备份。

保存错误、账本校验错误与备份错误分别显示：连接或校验失败在页面顶部提示，备份失败在顶栏徽标、备份卡片与备份中心内提示，暂停状态单独给出人工处理指引；备份失败时已保存的交易仍能查询，不应重新录入。窄屏（390px）可完成单笔录入、预览确认、备份中心操作与状态查看。
