# 阶段二：集中补记与业务模板

## 草稿与保存

在工作台选中日期，按 `b` 或点击「补记工作台」打开集中补记。该日期不会跟随午夜变动，左侧按作业分区切换（日常消费、转账 / 还款 / 余额、余额宝收益、淘宝订单、高级分录、模板与推荐）。
工作台的今日视图会在上海日期跨天或页面恢复前台后更新，手动选择的历史日期保持不变。补记恢复已有内容或待确认请求时保留原日期；已清空且没有未完成输入的旧草稿重新打开时采用工作台当前日期。录入日期非今天时显示提示，可用「新记录改用今天」修改后续录入日期，已有草稿不会随之改动。
填写一笔后点击「加入草稿」，或按 Ctrl+Enter；Tab 切换字段。「复制上一条」复用上一笔草稿，日期保持当前选中值。
所有账户与费用分类选择支持输入中文、账户名片段或空格分隔的关键词筛选，使用方向键和 Enter 或鼠标选择候选；搜索文字本身不能作为账户提交。各业务仍只提供允许使用的账户范围。
草稿可以逐笔取回修改或移除；高级草稿取回后继续编辑原文。关联处理草稿如需换订单，请移除后重新选择并确认。

基础输入及已加入队列的记录自动写入当前浏览器 localStorage，按账本目录身份隔离。页面刷新、服务重启、浏览器正常重启后可恢复。
浏览器存储写入失败会明确显示错误；另一标签页已修改草稿时拒绝覆盖，关闭再打开读取最新草稿。
草稿不在账本目录内，不参与正式余额及 Git 提交。清除网站数据、更换浏览器或使用会清理存储的隐私模式会失去本机草稿；这不是跨设备草稿同步。
转账/收益表格/订单处理的小表单只有点击「加入草稿」后的条目才进入可恢复队列。工作台旧的「待记便笺」仍只是会话便笺。

「整批预览并校验」显示每笔原文、目标文件及文件差异；后台逐笔组装候选完整账本，任一错误均阻止整个批次写入，错误标出第几笔。
确认整批入账后共用阶段一持久化写入协议，一个请求身份覆盖全批次；跨文件中断恢复和重复请求都不会重复新增。
保存超时后内容锁定，点击「重试原批次保存」核对原请求。已知预览版本冲突可取消预览，修改并重新预览。
保存成功与 Git 备份分开，阶段二没有启用自动同步。

## 模板与购物

快捷入口提供淘宝、超市、餐饮、水电费、余额宝、工资/奖金和话费。
在「模板与推荐」分区的「最近常用」选取近期有效交易组合，调整分类和账户后输入模板名称固定；使用同名保存更新，或在下方的「模板管理」中停用/重新启用。
模板不保存日期、金额或备注。关闭或尚未生效的账户不会作为模板默认值；全账本校验仍是最终写入门禁。

88VIP 默认金额就是实际付款。需要明细时展开商品与折扣，每项选择费用类别、金额及商品备注；优惠填写负费用项，合计必须等于实付。
每项备注写入 posting 的 `memo`，一般备注写入交易 `memo`。「随手记一笔」同样支持展开商品与折扣明细。历史普通多行记录点击「修改」会回填多行分录表单，可修改、增加或移除分录。
订单列表与详情的原备注同时展示交易备注及各分录备注，分录备注注明所属账户；读取不会改变原始账本。结算与退款使用明确显示的「本次处理日期」，独立默认上海当天，不沿用日常补记或原订单日期；未手动选择时跨天跟随今天，可就地选择历史日期。变更日期后重新选择账户并确认处理。订单处理草稿也显示该日期，已加入草稿的日期保持不变。

## 淘宝订单

购物付款方式分别选择「淘宝直接付款」或「淘宝先挂待付款负债」。挂账需要有效负债账户，直接付款也可使用信用账户。
下单生成费用；确认收货只结转待付款负债到实际付款账户，不再生成费用。支持部分结算并显示剩余未结清金额。

打开「淘宝订单」分区，在订单列表选择原交易（列表按未结清、已退款与历史记录标注状态），核对金额、处理方式和账户，勾选确认后加入草稿。
列表默认仅显示已标记订单及名称、备注或账户包含淘宝/天猫的历史候选，按日期倒序，每次显示 20 条；其他消费可通过「全部历史消费（手动认领）」查找。可组合搜索商户、商品、备注、订单号、金额或原文关键词，并按日期、状态和原付款账户筛选。「刷新订单」保留当前筛选条件，刷新或改变条件会清除旧关联，需重新选择原交易。列表展示原备注和来源文件行号，选中后可展开完整原始交易，核对商品明细及注释。
历史账本没有稳定订单号时，只提供交易建议，由用户确认实际语义；取消关联不会入账。
第一次确认的历史结算/冲回方式会限制后续关联处理，避免把同一历史负债同时当直接付款和未付款处理。

- 已付款退款：原费用负项 + 实际收到退款的资产或信用账户正项。
- 未结算负债冲回：原费用负项 + 原待付款负债正项。
- 部分退款选择原费用类别，不超过该类别和整个订单剩余额；多类别退款可分项加入同一批次。
- 快递赔偿等额外收入使用高级分录，不能作为退款自动冲费用。

`order-id`、`order-ref`、`order-action`、`order-amount` 为订单入口维护的元数据。
已存在关联处理时，先撤销相关记录再更正订单；关联处理记录需删除后重新录入，禁止改写金额后遗留旧关联状态。
删除结算若会造成已退款超过已付款，也会被拒绝。普通原文不能新增或篡改这些关联字段。

## 收益、工资和缴费

余额宝日期表显示已有原文与空缺日期，只将填写实际金额的空缺加入队列，不补零、不推算。
同一日新增和批次内重复都被拒绝；已有日期使用「更正」修改原记录，更正也不能撞上另一个已有日期。
全部收益保存到 `txs/category/yuebao.bean`，日期工作台跨文件展示。

工资/奖金选择收入账户和到账资产账户，填写到账金额、日期及备注；同月可有多笔，保留 salary 标签范围及收入侧省略金额。
话费保存到 `phone.bean`，水电费保持普通月份路由；更换付款账户不会改变业务路由。

## 转账、余额和高级原文

单笔和补记「高级分录」提供「多行分录表单（含预算权益）」：每行选择 Assets、Liabilities、Expenses、Income 或 Equity 账户，填写正负金额、币种和备注。支持消费加预算权益四行交易，也支持多商品、负优惠券和一个付款账户的购物单。界面按币种显示合计；启用某行「自动推导」会同时清空该行金额和币种，最终由完整账本预览校验。

历史记录逐行保留来源，修改账户、金额或 memo 不会重写其他分录的标签、注释与元数据；无修改时原文零差异。移除一行会同时移除该行附属元数据。带成本、价格、多行 memo、金额表达式或其他表单无法完整表示的记录继续使用原文高级编辑。业务记录模板与订单关联约束仍然生效，表单不能绕过这些限制。

转账金额表示转入账户收到的金额，手续费单列费用，转出金额为两者合计。
信用账户还款从资产转入负债账户，只有手续费计入消费。
余额断言检查所选日期开始时账户及其子账户的指定币种单位余额，不包括当天交易；核对日终余额请选次日。
界面展示预期、实际和实际减预期差额；最终以 Beancount 校验及容差为准。不符时拒绝写入，不增加 pad 或补差收支。

高级模式只接受一条交易（余额业务只接受一条 balance），保留多 posting、外币、标签/链接、交易及 posting 元数据、成本、价格、推导金额和权益辅助分录。
原文日期决定新交易路由，编辑保持原文件位置；未修改原文产生零差异。零金额只提示检查，不能依据备注自动补值。
