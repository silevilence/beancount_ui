# Grocy 联动实施审核与验收

日期：2026-10-19。范围：`ded611a` 之后的 Grocy 联动与独立订单收货实现及最终修复；需求来源为根目录 ROADMAP 对应阶段。审核分为规范与需求两条独立检查。

## Standards

未发现剩余的仓库规范硬性违规。检查了后端凭据保管、传输错误处理、写入锁、发送前持久化、恢复核对及撤销去重边界。

一项非阻塞的设计判断：库存操作状态的分支判断分布于发送、核对、撤销和页面展示中，存在 possible Repeated Switches。后续增加状态时可集中状态定义与允许的迁移；当前各处承担不同执行职责，尚不足以要求为本次验收改写整体结构。

## Spec

审核发现的 P1 问题已修复并复核通过：账务预览失效后，前端原先只能恢复同一个失败请求，可能锁住后续收货。现在后端先恢复并核对原账务写入，允许取消尚未应用的预览；已完成写入保持完成。收货流程可保留实收、结束未完成结算，再继续收货或重新预览账务。重复提交已取消的账务请求会被拒绝。

未发现其余阻塞性实现问题或额外范围扩张。部署验收仍有环境缺口：容器重建和真实 NAS 网络／凭据尚未验证，不视为本机测试已经覆盖。

审核汇总：Standards 为 0 项硬性违规、1 项非阻塞设计判断；Spec 的 1 项 P1 已修复，剩余 1 项部署环境验收缺口。

- 前端：`npm test -- --coverage`，32 个测试文件、276 项测试通过；语句 94.70%、分支 90.02%、函数 93.65%、行 95.50%，满足现有 90% 门槛。`npm run check`、`npm run build` 通过。
- 后端：`uv run pytest --cov=beancount_ui --cov-report=term-missing --cov-fail-under=90 -q --durations=12`，342 项通过、1 项真实 Grocy 测试默认跳过；覆盖率 92.05%，满足 90% 门槛。耗时 11 分 12 秒。现有 Starlette/httpx 弃用提示 1 项，无测试失败；默认跳过的真实接口测试已另行启用并通过。
- 静态检查：`uv run ruff check .` 通过。
- 真实接口：`uv run pytest tests/test_grocy_live.py -q -s`，独立运行 1 项通过。使用官方 Grocy 4.7.1、PHP 8.5.11、SQLite 3.53.4，仅监听回环地址，账本和状态均为项目外一次性测试副本。

真实接口测试覆盖产品／位置／单位／采购地点、单位换算、120 元购买 2 箱共 24 瓶、分批收货、账务结算、部分开封导致批次拆分、转移、消耗、成功响应丢失，以及远端已生效但本地恢复至仅有预览的旧备份。恢复后无重复入库；测试结束库存为 21 瓶，等于入库 24 瓶减去消耗 3 瓶。

浏览器在隔离环境走通缺货告警预填购买、保存已付款订单、独立实收、同步成功和库存刷新。收货前后账本指令数保持 21，没有新增 0 元占位或第二笔消费。桌面及 390px 窄屏操作可用，窄屏未发现横向溢出；设置页只读检测显示实际版本 4.7.1。

故障与兼容测试另覆盖延迟完成、查询失败、部分日志、多事务冲突、撤销与后续操作、重复点击、旧购买指纹、旧补记草稿及 Grocy 未配置场景。真实 API 测试默认跳过，必须按 [使用与恢复说明](grocy-workflows.md) 显式指定隔离实例。

## 尚未完成的部署验收

当前机器没有 Docker，也没有可用的 NAS 联调地址和凭据。本次没有连接生产 NAS、修改家庭库存或真实账本。以下检查保留在 ROADMAP 最后一项，完成前不勾选整个部署验收任务：

1. 在隔离 Docker 环境挂载账本、完整 state 和 Grocy 数据卷，保存购买及部分收货；重建应用容器后核对订单、实收、操作编号和远端日志，确认没有历史入库重放。
2. 在容器网络中验证实际 Grocy 地址／子路径、API 权限及断连恢复，再验证持久卷备份恢复。模拟版本与权限错误的自动测试不能替代真实镜像升级后的检查。
3. 具备 NAS 访问条件后，核验后端到 Grocy 的连通性、实际版本、访问门禁和受保护的持久目录；使用专门测试产品完成最小写入验证，并按现场流程清理。

账本 Git 备份不包含应用 state 和 Grocy 数据卷。恢复旧 state 时未知操作不会自动重发；若备份早于全部预览记录，系统无法重建已经丢失的意图，必须先停止原执行并人工对账。完整备份与恢复步骤见 [Grocy 使用说明](grocy-workflows.md)。
