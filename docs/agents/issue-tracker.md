# Issue tracker: ROADMAP

本项目使用本地 Markdown 管理任务，`ROADMAP.md` 是唯一任务清单。
不使用 `.scratch/`，不为任务创建独立 issue 文件或远端 issue。

## 任务约定

- 沿用现有「计划中 / 开发中 / 已完成」分区及阶段组织。
- 每个任务使用一个顶层复选框条目，包含标题、预计工作量、
  子任务、依赖和验收标准；新增实现任务通常按 1—3 天拆分。
- 创建前检查现有条目，优先补充匹配任务，避免重复。
- 使用任务完整标题定位；有重名时结合阶段或分区定位。
- 详细 PRD 或分析材料可放在 `docs/` 并由任务链接引用，
  但可执行任务和进度仍统一维护在 ROADMAP。
- 保留无关任务、原有说明、链接和阶段归属信息。

## 分流与进度

- 分流结果写在对应任务下的缩进行：
  `Status: needs-triage`
- 可用值及含义见 `triage-labels.md`；一个任务仅保留一个当前值。
- 旧任务未标注时视为待分流，不在初始化时批量补写。
- 分流标签和开发进度分别维护：开发进度由所在分区及复选框表示。
- 开始实施时移入「开发中」，保留来源阶段及依赖信息。
- 满足验收标准后移入「已完成」，勾选任务并记录验证结果。
- `wontfix` 表示不执行，保留理由和未勾选状态，不计作已完成。

## 技能操作映射

- 「发布到 issue tracker」：在 ROADMAP 中创建或更新任务。
- 「读取 ticket / issue」：读取对应条目及其引用的资料。
- 「添加评论」：在任务下追加带日期的备注，保留历史记录。
- 「应用标签」：更新任务下的 `Status:` 行。
- 「领取任务」：先移入「开发中」，必要时记录负责人。
- 「关闭任务」：完成并验收后移入「已完成」；
  决定不执行时使用 `wontfix` 并记录理由。

## 依赖与探索任务

- 依赖通过任务标题明确引用；所有前置任务完成后才能解除阻塞。
- 挑选可执行任务时，按 ROADMAP 顺序查找依赖已满足、
  尚未开始且标记为 `ready-for-agent` 的条目。
- 使用 wayfinder 时，探索主题、子任务、结论及待解问题
  都记录在 ROADMAP 对应主题下；详细研究材料可链接至 `docs/`。
